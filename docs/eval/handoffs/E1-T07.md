## Decisions made
- **依赖注入 judge_fn**，而非 scorer 内部 `from evals.common.judges import call_judge` —— Why: scorer 是纯计算（precision/recall/f1），让 caller（E1-T08 task 文件）拼装 `judge_fn = lambda g, c: call_llm(model=j.model_id, prompt=j.prompt_body, ...)`，scorer 不持有 LLM 客户端 = 单测无外部依赖。Follow-up: E1-T08 接通 inspect-ai `@scorer` 时，把 judge_fn 通过 `state.metadata["judge"]` 注入。
- **贪心 one-to-one match**（早绑定，第一个 True verdict 即消费 golden） —— Why: PRD 没规定 Hungarian / 最大流；review F1 baseline 数字对 noisy judge 不敏感，贪心足够；二次 matching 让算法复杂度变 O(|G|³) 而无可观察收益。Follow-up: 如果未来 G1 gate 出现「分数贪心 vs 全局最优 diff > 5%」事件再换。
- **`f1` 在 0 + 0 时返回 0.0** 而不是 NaN —— Why: gate 计算与跨 run 比较都假设 `f1 ∈ [0, 1]`；NaN 会让 `delta = new - prev` 变 NaN 然后 silently mask 真实 regression。Follow-up: none。
- **两侧都空 = vacuously perfect (1.0/1.0/1.0)** —— Why: 算上「啥都没漏 + 啥都没乱报 = 100 分」；但同时 empty golden + non-empty candidate 必须是 precision=0（全 false positive），empty candidate + non-empty golden 必须是 recall=0（全 miss）。这三种 boundary case 都单测覆盖。Follow-up: none。
- **`review_overlap_scorer()` 落 NotImplementedError** 而非完整 inspect-ai 接线 —— Why: inspect-ai 0.3.220 的 `@scorer` 接口需要 `state: TaskState` / `target: Target` 等结构，而 E1-T06 review solver 还没确定 `state.output` 的字段名（被 blocked）；纯函数 + occupier shim 把 wiring 决定推迟到 E1-T06 unblock。Follow-up: 真实 inspect-ai 接线随 E1-T06 重新解 blocker 时一起做。
