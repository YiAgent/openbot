## Decisions made
- `evals/datasets/manifests/` 也加 `__init__.py`（而非 `.gitkeep`）—— Why: task 的 Deliverables 行 `evals/{common,solvers,scorers,datasets/manifests,tasks,scripts}/__init__.py` 用 brace expansion 字面包含 `datasets/manifests`，按字面 AC 落实更不容易在下一个 task 重读时产生歧义。空 `__init__.py` 对纯数据目录无副作用，且 manifests 后续如果想被 import-as-resource 也已经是包。Follow-up: none。
- `evals/datasets/__init__.py` 也加了（虽然 brace 不含它）—— Why: 没有 `__init__.py` 会让 `datasets/manifests` 变孤儿子包；统一全部 7 个目录为 namespace package 更一致。Follow-up: none。
- README 显式区分 active / 🕒 deferred suite 两栏 —— Why: AC 要求 "列出全部 v0.1 suite 名"，而 task-list.md §"范围调整" 把若干 suite 标 🕒 deferred 但仍属 v0.1 范围（解冻后启动）。把它们一起列出并打 🕒，可避免下一个 task 误以为 README 漏写。Follow-up: 解冻时间到再补 task 文件，README 表格里 status 列同步更新。
- 没有把目录补成 PRD §6.1 列出的具体 `.py` 模块名（`config.py` / `langsmith.py` / `openbot_review.py` 等）—— Why: 那些是 E0-T05 起的后续 task 的 Deliverables，本 task 仅要骨架 + 占位 `__init__.py`，不越界。Follow-up: 由 E0-T05、E1-T02、E1-T03、E2-T01 等任务依次填充。
