## Decisions made
- 把 `--help` 的内容做成 **structured `(field, hint)` 列表 + epilog 渲染**，而不是直接 docstring 写死 —— Why: E1-T02 真接通时需要把这两个常量 `REQUIRED_RUN_METADATA_FIELDS` / `EXPERIMENT_NAME_PATTERN` 改成校验逻辑的真值来源（**single source of truth**：`--help` 与实际校验逻辑共用同一个常量）。Follow-up: E1-T02 改 `main()` 时复用这两个常量去对比 LangSmith run.metadata。
- PRD §10.1 文本块写的是 14 行字段，但实际数行是 15（含 `triggered_by`）—— Why: 原 PRD §10.1 列出顺序是 14 行 + 「triggered_by」（一行注释，但仍是必填）。脚本里在常量列表内联了一条 NOTE 注释解释，把字段数与 PRD 字面对齐 +1。Follow-up: 如未来 PRD §10.1 增删字段，改这个常量 + 同步 baseline-log.md 「dataset_version」字段表。
- 非 `--help` 路径返回 exit code **2**（而非 0 或 1）—— Why: 0 容易被 CI 误判为「校验通过」，1 容易被 wrapper 当成「校验失败可恢复」；2 在 POSIX 习惯里表示 misuse / not-implemented，CI 拿到 2 时不会以为「这条 run 合规」。Follow-up: E1-T02 真接通时改成 0/1（contract pass / contract fail）。
- CI 加 `eval-validate-langsmith` job 写在 `ci.yml` 而非新文件 —— Why: 仅一个 step（跑 `--help`），单独建 workflow 文件会让 `.github/workflows/` 散；同时通过 `if: needs.detect.outputs.has_python == 'true'` 沿用现有 detect gate，零额外维护。Follow-up: 真接通后再判断是否拆出 `eval.yml`（E3 milestone 会引入 eval scheduler workflow，那时一并整理）。
- 没有给脚本写 pytest —— Why: Deliverables 列的是「脚本 + 含 --help；CI placeholder job」，不含单测；E0-T05 才开始要求脚本配单测。`--help` 输出由 CI job 自动 smoke。Follow-up: E1-T02 真接通时补 unit test 校验 metadata schema。
