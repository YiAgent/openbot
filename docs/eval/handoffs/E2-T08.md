## What was produced

- `evals/scorers/patch_tests.py` — pure, framework-free SWE-bench grading. Public surface: `PatchScore` (frozen dataclass with `.to_dict()`), `score_patch(fail_to_pass=..., pass_to_pass=..., test_results=...)`, and `aggregate_resolved_rate(scores)`. Implements the upstream rule: a sample is **resolved** iff every `FAIL_TO_PASS` test passes after the patch *and* every `PASS_TO_PASS` test still passes. Missing tests count as failures (we can't credit a pass we never observed).
- `tests/eval/test_patch_tests_scorer.py` — 10 unit tests pinning: full resolved path; one FTP still failing; PTP regression; missing test; ERROR / SKIPPED both count as failures; vacuous empty-spec case; JSON-serializability via `to_dict`; aggregate resolved rate over a mixed batch; a Django-shaped fixture mirroring `swe_bench_lite/django__django-11099` to document the upstream alignment.

The scorer is intentionally a pure function (no `inspect_ai`-only imports) so future consumers — `evals/tasks/swe_bench_lite.py` (E2-T11) and `evals/solvers/openbot_fix.py` (E2-T07) — can both plug into it without coupling. That decoupling is what let this task land before its declared dep (T07) ships.

## Decisions made

- **Pure functions, not an `@scorer` decorator** — Why: this lets the same code grade outputs from (1) the upstream `inspect_evals` SWE-bench task, (2) a future Modal-backed OpenBot fix solver, and (3) any one-off CLI use that takes a test-results JSON. Wrapping with `@scorer` is the consumer's job (E2-T11 will do that).
- **Missing tests = failures** — Why: SWE-bench's harness treats unobserved required outcomes as failures (the patch hasn't proven it satisfies the spec). Reporting them separately as `missing_tests` lets downstream tooling distinguish "test ran and failed" from "test never ran at all" for debugging.
- **SKIPPED counts as failure** — Why: SWE-bench's leaderboard does not credit skipped tests as passes. Pinned by `test_skipped_test_counts_as_unexpected_failure`.
- **Empty-spec vacuously resolved** — defensive; real SWE-bench samples always have at least one FAIL_TO_PASS, so this branch is unreachable in practice but explicit beats implicit.
