## Decisions made

- **Source = local .eval log**, not LangSmith query — Why: the Inspect AI runner writes complete metric data to a local `.eval` binary, and `inspect log dump` already exists to convert it to JSON. Going through LangSmith adds a network dep, requires inspect-ai → LangSmith bridge config, and would block this task on E1-T04's project-routing wire-up. For v0.1, local log is enough; LangSmith query mode is a flag we add later. Follow-up: `--from-langsmith <run_id>` flag added once inspect-ai → LangSmith logging is configured.
- **Pass rate threshold = F1 ≥ 0.5** — Why: arbitrary but defensible — F1 < 0.5 means either precision OR recall is below 50%, which is a real signal of bad performance. Same threshold appears in PRD §9 G2 hard-block region (10% drop from baseline); 0.5 is a reasonable absolute floor. Follow-up: tune once we have multiple baselines for comparison.
- **Pass mean_f1 / stderr through as-is from `inspect log dump`** — Why: inspect-ai's reducer (mean + stderr) is the canonical aggregation; reimplementing them in this script would risk drift. Trust the runner's numbers. Follow-up: none.
- **Top-5 by cost** — currently all $0 (see E1-T06 follow-up about langchain token tracking). The script is correct; the input data is the gap.
