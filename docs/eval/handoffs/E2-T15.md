## Decisions made

- **Relative drop, not absolute** — PRD §9 says "↓ ≥ 5%". `(baseline - current) / baseline` is the only reading that makes the threshold scale-invariant (a 5% drop at F1=0.80 = 0.04 absolute is materially different from a 5% drop at F1=0.50 = 0.025 absolute). The test grid `test_review_gate_soft_warn_at_5_percent_drop` and `test_review_gate_hard_block_at_10_percent_drop` pin this interpretation.
- **G2 suppresses redundant G1 row** — Why: PRD §9 G1 and G2 are nested thresholds. When G2 trips, surfacing both rows would tell CI the same story twice and confuse the PR comment. The test `test_review_gate_hard_block_supersedes_soft_warn` pins this.
- **G6 derives `fail_safe_rate` from `failure_categories` when missing** — Why: the redteam scorer (E2-T13/T14) emits per-sample `failure_category` rather than an aggregate fail-safe rate, so the comparator computes it on the fly. Categories matching `none` are counted as safe; everything else is a breach. Pinned by `test_safety_gate_derives_fail_safe_from_failure_categories`.
- **Triage gate is a floor check, not a regression check** — PRD §9 G5 reads "label F1 < 0.55 (v0.1) / < 0.65 (v0.2)" — that is a hard floor, not a delta. So `evaluate_triage_gate` takes only `current`; no baseline needed.
- **CLI exits 1 on hard/block-release, 0 otherwise** — Why: this is the documented contract that downstream CI workflows will key off of. Future workflow YAML (E3-T01 `eval-regression.yml`) only needs `compare_runs.py` to exit non-zero to fail the build.
- **`Literal[…]` types for `GateStatus` / `GateBehavior` instead of an Enum** — Why: keeps the public surface JSON-serializable and matches how Inspect AI / LangSmith already represent metadata as plain strings.
