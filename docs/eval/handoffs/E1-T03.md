## Decisions made
- 把 `dataset_version` / `dataset_sha256` 列为 **keyword-required** 参数 —— Why: PRD §10.1 这两个字段来自 manifest（E0-T03 写了 spot-check 模板，E2-T01 落 Martian manifest）；不能从 cwd 自动推。让 caller 显式传，避免「忘传 → fallback 到默认 → 跑出错误 baseline」的隐式失败。Follow-up: E1-T08 Martian smoke task 调用时从 `evals/datasets/manifests/martian_*.yaml` 读这两个值。
- `triggered_by` 走「GITHUB_ACTIONS env 优先 + `OPENBOT_EVAL_TRIGGER` 兜底」—— Why: GitHub Actions runner 自动注入 `GITHUB_ACTIONS=true`；cron / 本地手跑没有这个 env，所以我们给一个显式 override env 名（`OPENBOT_EVAL_TRIGGER`）让 cron 脚本能注入 `cron`。Follow-up: E3 milestone cron workflow 写 step env `OPENBOT_EVAL_TRIGGER: cron`。
- `prompt_version` / `workflow_version` 走 try/except ImportError 而不是硬要求模块存在 —— Why: v0.1 Week 1 skeleton 里 `openbot.prompts` / `openbot.workflows` 还不存在；E1-T06 之前调用 metadata 会自动 fallback 到 `"unknown"`，保留运行能力。等真模块上线后测试会失败（`assert == "unknown"`），强制 reviewer 同步。Follow-up: `openbot.prompts.__version__` / `openbot.workflows.__version__` 落地时改这两个测试断言。
- 用 `__import__(modname, fromlist=["__version__"])` 而非 `importlib.import_module` —— Why: `__import__` 配 `fromlist` 才会返回 submodule（而非 top-level），刚好适配 `openbot.prompts` 形式的 nested package。Follow-up: none。
- belt-and-braces 自校验放在函数里（`REQUIRED_RUN_FIELD_NAMES - metadata.keys()`） —— Why: spec 改了 `_metadata_spec.py` 加字段但忘改 `metadata.py` 时，错误在 `collect_run_metadata` 调用点炸而非到 LangSmith 后才发现。Follow-up: none。
