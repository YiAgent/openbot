## Decisions made
- 三本日志都用 **YAML schema 示例 + 字段表** 描述每行，而不是 Markdown 表格 row —— Why: 字段数（11–12 个）超过 Markdown 表格能舒服承载的宽度；下游脚本（E3 `export_run_summary.py`）追加行时也是用 YAML block 更省事，避免 Markdown 表格 escape pipe / 换行的坑。Follow-up: 如 E3 想改 schema，更新「如何记录」字段表并升 `## Entries` 段的格式版本说明。
- `baseline-log.md` 把 release 之外的四类触发（judge-model / judge-prompt / scorer-logic / dataset-bump）也列入 —— Why: PRD §9「Baseline 治理」第二条要求 judge/prompt/scorer 改动必须**重跑 baseline 并 PR review，写入 baseline-log.md**，所以本 log 不是 release-only 的。Follow-up: none。
- `judge-version-log.md` 引入 `linked_baseline_entry` 字段做交叉引用 —— Why: PRD §10.3 与 §9 是同一治理事件的两面（前者记前后分数，后者记 baseline 切换决定），手动维护交叉链让 reviewer 容易复核「这个 PR 是否 baseline-log 也补了」。Follow-up: 如果以后改成自动化（E3+），可以把 link 改成自动生成。
- `flaky-samples.md` 没列具体 sample，只放占位 + 月度 review checklist —— Why: 现在没 sample 跑过，自动登记机制（`scripts/export_run_summary.py`，E3-T03）也还没接入；空表加 placeholder 即可满足 AC。Follow-up: 等 E3-T03 落地后第一次 weekly run 触发首条登记。
- `dataset-spot-check/` 用 `.gitkeep` 而不是 `__init__.py` —— Why: 这是文档目录（每个 dataset 一个 `.md`，例 `internal_prs_v1.md`，PRD §7.2 末段），不是 Python 包；与 E0-T02 里 `evals/datasets/` 必须是 namespace package 是不同语境，不混用。Follow-up: none。
