## Decisions made
- **Hash-pin** 而不是「读 JUDGE_PROMPT 真值再 assert」 —— Why: hash pin 是 single source of truth，任何 prompt 字节（包括空格 / 换行）变化都会 fail，连「无意义重排」也兜底。直接 assert 字符串相等需要在测试里复制整段 prompt，反而容易因复制错误产生假阳性。Follow-up: 编辑 prompt 时按 `_JUDGE_PROMPT_HASH` test 失败信息里给出的新 hash 替换 + bump version。
- frozen `dataclass` 而不是普通 class —— Why: PRD §10.3 末段「Judge 锁定到 release」—— 一旦 release 出报告，那一份 (model, version) 必须不可变；frozen 让代码层就 forbid 半 mutate。Follow-up: none。
- `fingerprint() -> tuple` 而不是 `__hash__` —— Why: tuple 可序列化进 LangSmith run metadata；`__hash__` 是不透明 int，没法溯源。Follow-up: E1-T07 scorer 在每次 `call_judge` 时把 fingerprint 写进 `score_payload`。
- `_JUDGE_PROMPT_BODY` 故意写得短而 generic —— Why: 真正的 scorer-specific framing 落在 `evals/scorers/review_overlap.py`（E1-T07）等模块里，judge 本身只承担「judge 角色 + 输出 JSON shape」。Follow-up: 如未来要分多个 judge prompt（不同 scorer 用不同 prompt），再扩成 `Dict[str, str]` 表，但 v0.1 不需要。
- 同时 flip 了 E1-T03 的 `test_judge_prompt_version_fallback_zero` 测试 —— Why: 那个测试是 E1-T03 handoff 「Open follow-ups」里预报的 intentional gate；当 E1-T05 上线 `JUDGE_PROMPT_VERSION` 时它就该改。本 commit 同时改完防止 `make check` 红。Follow-up: none。
