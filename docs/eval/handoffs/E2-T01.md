## Decisions made

- **Dataset name `martian_2026w20` (week 20 of 2026 = May 11-17)** — Why: PRD §7.2 wants a snapshot-style name so future re-locks (`martian_2026wXX`) coexist with this one in `evals/datasets/manifests/`. The smoke fixture stays under `martian_smoke_v1` and is *not* deprecated — it is the cheap CI smoke target while the full lock runs as the baseline (E2-T02).
- **Diff fetched via authenticated GitHub REST API instead of `patch-diff.githubusercontent.com`** — Why: the unauthenticated `.diff` redirect endpoint rate-limits (`429`) after ~30 requests, which made deterministic builds impossible. The REST API with `Accept: application/vnd.github.v3.diff` returns the exact same diff bytes and inherits the user's `gh` auth quota (5k req/h).
- **Finding `file` left empty / `line` set to null** — Why: upstream Martian gold comments only carry `comment` + `severity`; they do not pin file/line. The smoke heuristic judge in `review_martian.py` already tolerates empty `file` after the patch in this branch. The full LLM judge (PRD §10.3, due in the E2 baseline run E2-T02) does semantic matching, so the missing line numbers are not a blocker.
- **`public: true` on the manifest** — Why: this is the comparable public baseline. PRD §13.2 fail-safe applies to the smoke fixture (`public: false`); the real Martian numbers belong in the public LangSmith project so downstream consumers can compare apples-to-apples. E1-T10 routing already gates on `public:`.
- **Builder uses `Authorization: Bearer <token>` from `gh auth token` as fallback** — Why: anyone running the script will have `gh` configured (it is the canonical OpenBot dev requirement). Falling back to env-var first means CI can drop in `GITHUB_TOKEN` without touching the script.
