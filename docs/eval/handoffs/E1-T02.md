## Decisions made
- task spec 说「12 个必填字段」但 PRD §10.1 实际列 14 行 + 末尾「+ triggered_by」共 **15** —— Why: spec 在 task-list 上是粗估；PRD 是 source of truth。测试 hard-pin `len(REQUIRED_RUN_FIELD_NAMES) == 15`，未来 PRD §10.1 增删字段时测试会 fail，迫使 reviewer 复核。Follow-up: PRD §10.1 改字段 → 改 `_metadata_spec.py` → 改 hard-pin 数。
- 抽出 `_metadata_spec.py` 而不是把常量留在 `langsmith.py` —— Why: `scripts/validate_langsmith_run.py --help` 必须在没装 langsmith 时也能跑（E0-T04 CI placeholder job 走这个路径）；如果常量住在 `langsmith.py` 里就会顺带 import `langsmith`（即便 lazy 也容易意外触发）。`_metadata_spec.py` 零依赖，所有 surface 共享。Follow-up: E1-T03 metadata.py 也复用同一份 spec。
- `init_client()` 用 keyword-only `public=False` flag 路由两个 project —— Why: PRD §13.2 锁定双 project 隔离；调用点显式写 `init_client(public=True)` 比按 dataset 名脑补路由更清楚。E1-T10 在 caller 层把 `dataset.public` 字段翻译成 flag。Follow-up: E1-T10 实现 `route_project(dataset_version: str) -> bool`，本模块不需要改。
- `_LangSmithLike` Protocol 而不是 import `langsmith.Client` 做类型 —— Why: 测试用 `MagicMock`，对 type 系统而言是「duck typing」；用 Protocol 让 mypy / pyright 不抱怨。Follow-up: 真正调用 LangSmith API 时（E1-T04 集成测试）才把 Protocol 收窄。
- `log_sample` 用 `client.create_feedback(key=f"sample::{sample_id}")` 暂代 ——Why: PRD §10.2 没规定 sample 在 LangSmith 上落 feedback / artifact / dataset 哪种 entity；E1-T04 真接通时会调整路由（feedback 更接近 score 语义，更省 storage）。Follow-up: E1-T04 真集成测试时确认 LangSmith API 这条路径正确。
- 留下 `import importlib.util` 测试 script-vs-library 一致性 —— Why: 两份相同常量更新时容易漏一份，加一条 wiring assert 自动捕获 drift。Follow-up: none。
