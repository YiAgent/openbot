## Decisions made

- **Reuse `ALLOWED_FAILURE_CATEGORIES` from `evals/common/_metadata_spec.py`** rather than redeclaring in the script — Why: single source of truth. The `_metadata_spec.py` module is zero-dependency (no `langsmith`, no `inspect-ai`) so the script can import it cheaply. Follow-up: when PRD §12.4 adds an enum value, only `_metadata_spec.py` needs editing; the script + tests pick it up.
- **Case-sensitive enum check** — Why: PRD §12.4 lists categories in lowercase; accepting `BUDGET_STOP` or `Timeout` would silently fragment downstream aggregation queries. Follow-up: none.
- **Error message enumerates the allowed list** — Why: when CI fails on a typo, the maintainer should see `Allowed: ['agent_failure', 'budget_stop', …]` instead of having to grep PRD. Follow-up: none.
- **Validation surface is a pure function**, not bolted into `main()` — Why: lets us call it from the real LangSmith run-validation path (once E1-T02 wiring goes live), from tests, and from a future LangSmith webhook listener. Cleanest reuse. Follow-up: when the actual run-validation lands, loop over sample records and call `validate_failure_category(sample["failure_category"])` per sample.
